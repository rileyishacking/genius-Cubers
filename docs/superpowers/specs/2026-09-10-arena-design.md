# الحلبة — تصميم صفحة المنافسة

**التاريخ:** 2026-09-10
**الحالة:** معتمد، جاهز لخطة التنفيذ

---

## ١. الغرض

صفحة `/arena` يحل بيها الزائر المكعب الثلاثي الأبعاد الموجود بالموقع تحت مؤقّت،
وينحفظ وقته، ويتنافس وياه الباقين على لوحة صدارة.

حالياً رابط «الحلبة» بالـ Nav يأشّر على `/#play` (قسم اللعب بالصفحة الرئيسية) —
مكان مؤقت. الصفحة الجديدة تاخذ محله.

## ٢. النطاق

**داخل النطاق**
- صفحة `/arena` جديدة
- إعادة استعمال `CubePlayground` الموجود، مو نسخة ثانية منه
- تسجيل وقت الحل بدقة الملي ثانية
- سجل شخصي: أفضل وقت، آخر المحاولات
- لوحة صدارة بأفضل الأوقات
- بوابة تسجيل دخول قبل حفظ الوقت

**خارج النطاق (متعمّد)**
- معدّل ٥ محاولات (ao5) والإحصاءات المتقدمة
- تصنيفات لأنواع مكعبات مختلفة
- الخلطات الرسمية المعتمدة (WCA scrambles)
- مباريات مباشرة بين لاعبين

هاي كلها ممكن تنضاف بعدين. ما نبنيها الآن لأنها ما مطلوبة.

## ٣. القرار المعماري: طبقة بيانات بواجهة واحدة

Supabase مو مربوط بعد، بس المستخدم قرر يشترك بيه. فبدل ما ننتظر أو نبني
شي نرميه، نعرّف **واجهة تخزين** وننفّذها محلياً الآن.

هذا نفس النمط المعتمد أصلاً بـ `src/auth/AuthContext.tsx`، اللي مكتوب بيه صراحة
إنه نسخة محلية مؤقتة وإن التبديل لـ Supabase يمس ذاك الملف وحده.

```ts
// src/arena/scores.ts
export type Solve = {
  id: string;
  name: string;      // اسم اللاعب وقت الحل
  email: string;     // المُعرّف
  ms: number;        // زمن الحل بالملي ثانية
  moves: number;
  at: string;        // ISO
};

export interface ScoreStore {
  submit(solve: Omit<Solve, 'id'>): Promise<Solve>;
  topTimes(limit: number): Promise<Solve[]>;   // مرتبة تصاعدياً بالزمن
  myTimes(email: string): Promise<Solve[]>;    // الأحدث أولاً
}
```

تنفيذ واحد الآن (`localStore`)، وتنفيذ ثاني لاحقاً (`supabaseStore`).
الصفحة تستورد `store` مو التنفيذ، فالتبديل سطر واحد.

## ٤. تعديل `CubePlayground`

المكوّن أصلاً يكشف الحل ويوقف المؤقّت (السطر ١١٦–١١٧). الإضافة نداء اختياري:

```ts
type Props = { onSolve?: (r: { ms: number; moves: number }) => void };
```

**نقطتان حرجتان اكتُشفتا بقراءة الكود:**

١. **دقة الزمن.** المؤقّت يعيّن حالة `elapsed` كل ١٠٠ms عبر `setInterval`،
   فقيمتها ممكن تتأخر لحد عُشر ثانية. الوقت المُرسل لـ `onSolve` **لازم**
   يُحسب لحظة الحل مباشرة:
   `performance.now() - timer.current.t0`
   ولا يُقرأ من حالة `elapsed` أبداً.

٢. **الإغلاق القديم (stale closure).** `refresh()` تعيش داخل `useEffect`
   بمصفوفة اعتماديات فارغة، فلو استعملت `onSolve` مباشرة راح تتجمّد على
   أول قيمة. الحل: نحتفظ بالنداء داخل `useRef` ونحدّثه كل render.

الصفحة الرئيسية تستدعي `<CubePlayground />` بلا `onSolve`، فسلوكها ما يتغيّر.

## ٥. صيغة عرض الوقت

`clock()` الحالية تعرض `mm:ss` بلا أجزاء الثانية — ما تكفي لمنافسة سرعة.
الحلبة تستعمل `mm:ss.cc` (جزء من مئة). دالة تنسيق جديدة في `src/arena/`،
والدالة الحالية تبقى كما هي للصفحة الرئيسية.

## ٦. تدفّق المستخدم

```
يضغط «اخلط المكعب»
      ↓
أول حركة تشغّل المؤقّت        (سلوك موجود)
      ↓
يحل المكعب → الأوجه الستة تكتمل
      ↓
المؤقّت يتوقف + onSolve({ ms, moves })   (جديد)
      ↓
   مسجّل دخول؟
      ├── نعم → يُحفظ الوقت + يظهر بلوحة الصدارة + رسالة نجاح
      └── لا  → تظهر دعوة تسجيل مع الوقت محفوظ مؤقتاً بالذاكرة؛
                لو سجّل خلال نفس الجلسة يُحفظ الوقت، وإلا يُهمل
```

قرار: الوقت المُعلّق يُحفظ بحالة React فقط، مو localStorage — لأن حفظه
يفتح باب تلاعب أسهل بلا فائدة حقيقية.

## ٧. بنية الصفحة

1. عنوان وشرح قصير
2. المكعب والمؤقّت (`CubePlayground` مع `onSolve`)
3. سجلّك: أفضل وقت + آخر المحاولات (يظهر فقط للمسجّلين)
4. لوحة الصدارة: جدول بأفضل الأوقات مع الأسماء

يعيد استعمال نماذج التصميم الموجودة (`.wrap`, `.section-head`, `.pg-*`)
حتى ينسجم مع باقي الموقع.

## ٨. الأخطاء والحالات الحدّية

| الحالة | التصرّف |
|---|---|
| `localStorage` معطّل | الصفحة تشتغل، الأوقات ما تُحفظ، وتظهر ملاحظة صريحة |
| بيانات محفوظة تالفة | تُتجاهل بهدوء ونبدأ بقائمة فارغة (نفس أسلوب `AuthContext`) |
| WebGL غير مدعوم | `CubePlayground` عنده حالة `failed` جاهزة تعرض رسالة بديلة |
| لوحة صدارة فارغة | حالة فارغة مصمّمة، مو جدول فاضي |
| المستخدم يسجّل خروج | سجلّه الشخصي ينخفي، لوحة الصدارة تبقى |

## ٩. الاختبار

- حل المكعب فعلياً بالمتصفح والتأكد إن `onSolve` ينادى مرة وحدة بس
- التأكد إن الوقت المُسجّل يطابق المؤقّت (وما متأخر ١٠٠ms)
- التأكد إن الصفحة الرئيسية ما تأثرت (`CubePlayground` بلا `onSolve`)
- دورة unmount/remount بين `/arena` وصفحات ثانية بصفر أخطاء بالـ console
- `localStorage` معطّل: الصفحة تشتغل بلا انهيار
- `tsc --noEmit` و`npm run build` ينجحون

## ١٠. الانتقال لـ Supabase

جدول واحد:

```sql
create table solves (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id),
  ms integer not null,
  moves integer not null,
  created_at timestamptz default now()
);
```

الخطوات: كتابة `supabaseStore` يحقق `ScoreStore`، تبديل الاستيراد،
وتبديل `AuthContext` لمصادقة Supabase الحقيقية. الصفحة نفسها ما تتغيّر.

## ١١. قيد معروف: لوحة الصدارة قابلة للتلاعب

أي وقت يُحسب بالمتصفح يقدر أي واحد يزوّره من أدوات المطوّر. هذا صحيح
بالتخزين المحلي، ويبقى صحيحاً جزئياً حتى مع Supabase لو السيرفر ما يتحقق.

**ما يُدّعى إن اللوحة محمية.** التخفيف الممكن لاحقاً: التحقق من معقولية
الزمن بالسيرفر، وتسجيل تسلسل الحركات والتأكد إنه يحل الخلطة فعلاً.
هذا خارج نطاق هاي المرحلة، ومذكور هنا حتى يكون القرار واعي مو غفلة.
